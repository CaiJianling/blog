## 项目理解

Laravel 13 + Inertia React 3 + Tailwind v4 博客系统。前台路由（`/`, `/blog`, `/blog/{slug}`, `/{permalink}` 兜底、`/tools`, `/nav`, `/links`）走 `app.blade.php` + PublicLayout；后台在 `auth+verified` 组，管理员专属页挂 `AdminMiddleware` 组。文章/页面正文是 Blocknote 块数组（存 JSON），目前只有 `Article.views` 计数（`BlogController::show` 里 `increment('views')`），**没有任何访问日志表**，前端无任何图表库。

## 功能一：文章卡片预计阅读时间

**计算**：`Article` 模型新增 `estimatedReadingMinutes(): int` —— 递归遍历 Blocknote 块提取纯文本（`content[].text`、link 内嵌 inline、列表 `children` 递归、codeBlock 字符串 content、table cells），按 400 字/分钟计算 `max(1, ceil(len/400))`。现算不落库，内容编辑后自动正确。

**数据**：`reading_time` 字段加入 `BlogController::index`（瀑布流卡片）、`HomeController::formatArticle`（首页卡片）、`BlogController::renderArticle`（详情页 meta 栏）。

**展示**（三处卡片/meta，i18n 加 `publicComment.readTime`="约 {{count}} 分钟阅读"）：
- `pages/Blog/Index.tsx` 卡片左下 meta 组（作者/日期旁）加 `Timer` 图标 + "X 分钟"
- `pages/Home.tsx` 最新卡片作者名旁加 "X 分钟"
- `pages/Blog/Show.tsx` 元信息栏日期后加 "约 X 分钟阅读"

**测试**：`tests/Feature/ReadingTimeTest.php` —— 模型方法（空内容=1、长段落=分钟数、codeBlock/table/link 参与计数）+ `/blog` 与文章详情 props 含 `reading_time`。

## 功能二：站点统计后台（左侧后台新增「站点统计」入口）

**数据采集**（新表 + 中间件）：
- 迁移 `create_page_views_table`：`visitor_id`(sha256,64)、`user_id?`、`page_type`(home/blog_list/article/tool/nav/nav_link/link/other)、`object_id?`、`path`、`referrer?`、`referrer_class`(direct/search/social/internal/external)、`browser?`、`os?`、`device?`、`ip_hash`(sha256+app.key 盐，不存明文 IP)、`viewed_at`（模型 `$timestamps=false`）；索引 `viewed_at`、`visitor_id`。
- `app/Http/Middleware/TrackPageViews.php`（bootstrap/app.php 注册别名 `track.pageviews`），套在全站 public GET 路由（含末尾 `{permalink}` 兜底路由）上：
  - 跳过非 GET、爬虫 UA（bot|crawler|spider|headless 等）；
  - 访客指纹：cookie `blog_visitor`（随机 32hex，365 天，Lax，Laravel 默认加密），DB 存其 sha256；
  - 60 秒内同 visitor+path 去重（Cache TTL 60s），防刷新灌水；
  - 新 `app/Services/UserAgentInspector.php` 纯 PHP 解析 browser/os/device（Edge→Chrome→Safari 顺序、WeChat/Android/iOS 等）；
  - referrer 分类：无=direct，同域=internal，baidu/google/bing/so/duckduckgo=y=search，weibo/weixin/zhihu/douyin/推特/face 等=social，其余=external；
  - article/tool 的 object_id 用 slug 查一次（try/catch 兜底）。
- 数据保留：`app/Console/Commands/PrunePageViews.php`（删 180 天前数据）+ `routes/console.php` 加 `Schedule::command('pageviews:prune')->daily()`。

**统计接口**：`StatsController@index`（AdminMiddleware 组内 `GET /site-stats`，`?range=7|30|90` 默认 30），聚合：
- overview：PV、UV、新访客、回访访客（条件 distinct 一条 SQL）
- series：按天 PV/UV 序列（补零）
- topPages：Top10 路径（article 类 join 文章标题）
- sources：referrer_class 分布 + 占比、外部 Top 参考来源
- profiles：browser/OS/device Top 分布
- paths：站内跳转 `referrer→path` Top 条目（"用户访问站点页面的途径"）+ direct 落地页分布

**前端页面** `pages/Stats/Index.tsx`（无新依赖，Apple 风格）：
- 复用 dashboard 卡片样式；`ui/toggle-group` 做 7/30/90 天切换（router.visit preserveScroll）
- 自绘 `components/stats/line-chart.tsx`（SVG 双折线+面积+悬停 tooltip）与 `bar-list.tsx`（横向条形列表，含占比），分别渲染趋势、Top 页面、流量来源、画像、访问路径
- 空数据态提示；i18n 新增 `siteStats` 命名空间（zh/en）

**侧边栏**：`app-sidebar.tsx` 管理员区（userManagement 之前）加 `{ title: 'siteStats.title', href: '/site-stats', icon: BarChart3 }`（沿用 `/users` 硬编码字符串惯例，避免 wayfinder 生成时序问题）。

**测试**：`PageViewTrackingTest`（访问文章页落库/爬虫不落库/60s 去重/百度 referrer→search）；`StatsPageTest`（admin 访问 200 + Inertia 组件 props 校验、非 admin 302、cookie 签发）；`npm run build` 重新打包（含 wayfinder 重新生成 routes）。

**约定**：PHP 改动后跑 `vendor/bin/pint`；最小测试集 `php artisan test --compact`（3 个新测试文件 + BlogIndexTest 回归）。
